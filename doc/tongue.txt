1. INTRODUCTION                                           *tongue-introduction*

tongue.nvim forces English in Normal mode and restores the input method you
were last typing with when you enter Insert or Terminal-insert mode.

It exists because the usual approach does not work for external Vietnamese
IMEs. GoTiengViet, EVKey, OpenKey and GoNhanh are processes layered on top of
`com.apple.keylayout.ABC`, so "Vietnamese" and "English" are the SAME macOS
input source. A plugin that switches input-source IDs cannot express the
difference at all. tongue.nvim drives the `tongue` CLI, which moves both the
layout and the IME process.

Two design properties are load-bearing:

- Nothing blocks the UI. A backend read costs 40-50ms, and the obvious
  implementation pays that on every exit from Insert mode.
- Mode tracking uses |ModeChanged|, not |InsertLeave|. `i_CTRL-C` leaves
  Insert mode WITHOUT firing InsertLeave (see |i_CTRL-C|), which would strand
  you in Normal mode with the IME still on, indefinitely.

==============================================================================
2. REQUIREMENTS                                           *tongue-requirements*

Neovim 0.10 or newer -- |vim.system()| is the only command runner that both
separates stderr from stdout and supports a timeout, and both matter here.

A backend on $PATH. Auto-detection takes the first one it finds, in order:

    macOS     tongue          https://github.com/xom11/tongue
              macism          https://github.com/laishulu/macism
              im-select       https://github.com/daehahn/im-select
    Linux     fcitx5-remote   (ships with fcitx5)
    Windows   im-select.exe
    other     supply your own, see |tongue-backends|

Note: the `tongue` crate on crates.io is an unrelated program. Do not install
it with `cargo install tongue`; use the repository above.

`tongue` comes first on macOS deliberately. macism and im-select read and write
input-source IDs, which is the weaker lever: with an external IME, "vi" and "en"
are the SAME input source and they cannot tell them apart. They are still worth
detecting -- macOS's own Vietnamese, Japanese and Chinese input sources are
served fine by them -- and |tongue-health| says so out loud when you land on one.

3. SETUP                                                         *tongue-setup*

                                                             *tongue.setup()*
>lua
    require("tongue").setup({
      backend = nil,    -- preset name or table, see |tongue-backends|
      english = nil,    -- override the resolved backend's English token
      notify  = true,   -- warn on backend failure (throttled, 30s per kind)
      timeout = 2000,   -- per-command deadline in milliseconds
    })
<
`backend` accepts a preset name as well as a table: >lua

    require("tongue").setup({ backend = "macism" })
    require("tongue").setup({ backend = "im-select" })  -- `im_select` too
<
`english` applies to whatever backend was resolved, auto-detected included, and
is validated against it. The common case needs nothing else: >lua

    -- macism is installed; this machine types on US, not ABC
    require("tongue").setup({ english = "com.apple.keylayout.US" })
<
Get `english` right, because macism will not tell you when you get it wrong.
Measured on macism 3.1.1: an input source that does not exist on this machine
makes it print "Input source ... does not exist!" on STDOUT and exit 0. Nothing
separates that from success, so a wrong `english` gives you a plugin that runs,
reports healthy, and switches nothing. Check first: `macism <id>` then `macism`
should read it back.

The deadline is enforced by the plugin, not merely passed to |vim.system()|.
That matters when writing a backend: vim.system's own timeout kills the process
it started but still waits for the stdout pipe to close, and a shell wrapper
running its work in a subprocess leaves a grandchild holding that pipe. Measured:
a wrapper forking `sleep 5` with timeout=200 called back after 5016ms; the same
script using `exec` came back at 202ms.

setup() is required. Nothing happens on `require` alone.

With no supported backend, and in SSH sessions, the plugin stays inert. That
is deliberate, not a failure: over SSH the input method that matters is the
client's.

`notify = false` silences runtime warnings only. A malformed `backend` or
`english` is always reported, because a config bug that silently disables the
plugin is the exact failure this plugin exists to prevent. Being inert is not a
config bug and stays silent.

                                                            *tongue.status()*
Returns a table describing the resolved backend and current state. Used by
|tongue-health|; also useful when reporting a bug.

==============================================================================
4. BEHAVIOUR                                                 *tongue-behaviour*

    starting Neovim         read once, remember it, force English
    entering Insert/Term    restore the remembered token
    leaving Insert          force English -- including <C-c>, macros, :normal!
    manual switch in Insert noticed on the way out, restored next time
    completion, i_CTRL-O    nothing; these never leave Insert
    FocusGained in Normal   re-assert English

All backend calls are asynchronous and single-flight: a burst of 60 mode
changes costs one process.

==============================================================================
5. CUSTOM BACKENDS                                            *tongue-backends*

A backend is a table: >lua

    {
      english = "1033",               -- token forced in Normal mode (required)
      get     = { "im-select.exe" },  -- argv, prints current token  (required)
      set     = { "im-select.exe" },  -- argv, token appended        (required)
      unknown = nil,                  -- token meaning "unrecognised"
      tokens  = nil,                  -- allow-list, nil = any single word
      note    = nil,                  -- shown by |tongue-health|, no effect
    }
<
`get` must print exactly one whitespace-free token. Output with interior
whitespace is REJECTED rather than cleaned up: readers that merge stderr into
stdout turn a stray warning line into one plausible-looking token, which then
gets stored and replayed as an argument forever.

If `tokens` is given it must contain `english`.

Presets: `require("tongue.presets")` -- `.tongue`, `.macism`, `.im_select`,
`.im_select_exe`, `.fcitx5`.

What has been run, and what has not:

macism          verified end to end on macOS 26.5.1, Neovim 0.12.4, macism
                3.1.1, against the real macOS Vietnamese IM. Auto-detected when
                tongue is absent; outranked by tongue when both are present.
                Reads cost ~22ms (tongue: ~40-50ms, it moves an IME too).
im-select.exe   driven end to end on Windows 11 ARM64, Neovim 0.12.4, as a
                hand-written backend. Auto-detection verified there too: uname
                says Windows_NT, the chain resolves im-select.exe, and `english`,
                `backend = "im-select.exe"` and a rejected malformed `english`
                all behave as documented. The pure specs (mode, sanitize,
                backend -- 33 tests) pass under Windows Neovim; the rest of the
                suite does not run there, because tests/fixtures/fake-im is a
                POSIX shell script. That is the harness, not the plugin.
im-select       not run. Same shape as macism; covered as a chain and as data.

Every OS chain, Linux and Windows included, is exercised from a Mac:
tests/backend_spec.lua drives resolve() through an injected prober rather than
asking the real machine.

==============================================================================
6. HEALTH                                                       *tongue-health*

>vim
    :checkhealth tongue
<
Reports which backend was resolved and why, runs one real read, and flags a
backend that writes to stderr on success or answers with something outside its
declared token set -- which is what a name collision looks like from here.

It also prints the resolved backend's `note` if it has one. That is where you
find out that macism or im-select cannot see an external IME: the plugin looks
identical from the outside whether it is enforcing English or merely reselecting
an input source that was never what made you type Vietnamese.

==============================================================================
7. LIMITATIONS                                             *tongue-limitations*

- Command-line mode counts as Normal. Correct for `:`, arguably wrong for `/`;
  the mode string cannot distinguish them.

- The SSH guard does not fire on Windows. It keys off $SSH_TTY, and Windows
  OpenSSH does not set it (measured on Windows 11 ARM64). So Neovim run over SSH
  into Windows DOES auto-detect im-select.exe -- and im-select.exe needs a
  foreground window, which an SSH session has none of, so it answers "0". Locale
  IDs are open-ended, so there is no allow-list to reject that: the plugin
  accepts "0" and remembers it as the layout to restore. Nothing is damaged and
  nothing useful happens. Editing over SSH into Windows is the one case where
  this plugin is better left out of the config.
- A switch takes as long as the backend takes (~200ms for `tongue`, which
  starts and stops an IME process). The window after leaving Insert where the
  switch has not landed cannot be closed from inside an editor plugin.
- A manual switch made while one of our commands is already in flight, and
  followed immediately by leaving Insert, is missed. It corrects itself on the
  next Insert session.
